## Назначение документа

Настоящий документ является инструкцией для написания статьи, описывающей реализованный в рамках хакатона функционал платформы подбора роботизированных решений. ## 1. Общая архитектура и запуск

### 1.1. Архитектура

Платформа построена по архитектуре **Client-Server**:

```
[Браузер (HTML/CSS/JS)] <-> [Express Server (REST API)] <-> [SQLite DB]
```

Фронтенд — одностраничное приложение (SPA) на vanilla JS без фреймворков. Серверная часть — Node.js + Express. Хранилище — SQLite (better-sqlite3).

### 1.2. Запуск для просмотра функционала

### 2.6. Экономическая модель (серверная часть)

**Что реализовано:**
- **Расчёт количества роботов:** `ceil(операции / (throughput × часы_в_год))` с корректировкой на доступность (0.95 по умолчанию), загрузку (0.85) и инфраструктурные факторы (ровность пола, шум, зарядка)
- **CAPEX** (сценарий покупки): оборудование + инфраструктура (15%) + ПО (10%) + интеграция (15%) + обучение (5%) + резерв (10%)
- **OPEX**: сервис + лицензии + электроэнергия + материалы + ремонт + управление
- **Годовой эффект**: экономия ФОТ (сокращение труда) + рост продуктивности
- **Срок окупаемости**: `CAPEX / (экономия − OPEX)`
- **ROI**: `(накопленный эффект за горизонт − инвестиции) / инвестиции × 100%`
- **NPV**: дисконтированный поток денежных средств
- **TCO**: CAPEX + сумма OPEX за горизонт с учётом замены компонентов
- **Амортизация**: линейный метод, срок задаётся пользователем
- **RaaS-модель**: арендная модель с ежемесячными платежами (ставка 2% от CAPEX/мес. по умолчанию)
- **Кредитная модель**: аннуитетные платежи, первоначальный взнос (20% по умолчанию)

**Где смотреть:**
- Серверная модель — `server/services/calculation.js` (функции `calcScenario`, `calcBaseScenario`, `calcRaasScenario`, `calcLoanScenario`, `sensitivityAnalysis`, `calcAll`)
- Расчёты на клиенте дублируют серверную логику для мгновенного обновления UI — `app.js` функции `calcScenarioLocal`, `calcLoanScenarioLocal`, `calcRaasScenarioLocal`

### 2.10. Иммитация и визуализация (2D-схема)

**Что реализовано (детально):**
- SVG-контейнер 800×450 с сеткой и зонами объекта

## 3. Нефункциональные аспекты

### 3.1. Контейнеризация
- `Dockerfile` — образ на Node.js 20 Alpine
- `docker-compose.yml` — сервис `robo-platform` на порту 3000, volumes для БД и загрузок

### 3.2. Безопасность
- Пароли хранятся в хеше (bcryptjs)
- JWT-токены для сессий (secret из переменной окружения `JWT_SECRET`)
- Разграничение доступа по ролям (middleware `authorize`)
- Изоляция проектов по `user_id`

### 3.3. Производительность
- SQLite с WAL-режимом
- Индексы на ключевых полях (`solutions.type`, `solutions.applicable_to`, `projects.user_id`, `parameters.object_type_id`)
- Расчёт экономики выполняется как на клиенте (для мгновенного UI), так и на сервере (для API)

## 4. Порядок написания статьи (рекомендация)

1. **Введение** — описание проблемы фрагментированности рынка роботизированных решений и целей платформы.
2. **Архитектура** — Client-Server, стек технологий (см. раздел 1).
3. **Пользовательский путь** — 4 шага мастера: выбор объекта → каталог → экономика → визуализация (как демо-запустить).
4. **Каталог и подбор** — фильтрация, поиск, сравнение (раздел 2.3).
5. **Видеокаталог** — автогенерация 223 роликов из CSV, кнопка «Видео» в карточках (раздел 2.11).
6. **Экономическая модель** — формулы, сценарии (purchase, RaaS, loan, base), What-if (разделы 2.4, 2.6).
7. **Визуализация** — 2D-схема, анимация, KPI (раздел 2.5).
8. **Экспорт и импорт** — PDF, Excel, CSV (раздел 2.9).
9. **Расширяемость** — как добавить отрасль, объект, решение или модуль (см. `docs/architecture.md`, раздел «Расширяемость»).
10. **Демо-accounts и запуск** — инструкции (раздел 1.2, 1.3).

---

## 5. Критерии для оценки в статье

- Статья должна содержать скриншоты или описание каждого из 4 шагов
- Все формулы должны быть приведены с указанием допущений
- Ссылки на исходный код по каждому модулю
- Описание того, как воспроизвести демонстрацию (запуск, аккаунты, сценарий)
- Указание на границы реализации (что реализовано полностью, частично, как прототип)
