# Архитектура платформы подбора роботизированных решений

## Общая архитектура

Платформа построена по архитектуре **Client-Server** с разделением на клиентскую и серверную части:

```
[Браузер] <-> [Express Server] <-> [SQLite DB]
  Frontend        API Layer          Persistence
 (HTML/CSS/JS)    (REST API)         (platform.db)
```

## Серверная часть

### Точка входа (`server.js`)

- Инициализирует базу данных и запускает сид
- Подключает все маршруты API
- Раздаёт статические файлы (фронтенд)
- Обрабатывает загрузку файлов
- Обслуживает SPA (все неAPI маршруты → index.html)

### Маршруты API

| Префикс | Модуль | Авторизация | Назначение |
|---|---|---|---|
| `/api/auth` | auth.js | Нет | Логин, регистрация, демо-вход |
| `/api/catalog` | catalog.js | Нет | Отрасли, типы объектов, решения |
| `/api/calculation` | calculation.js | Нет | Расчёт экономики, экспорт |
| `/api/projects` | projects.js | JWT | CRUD проектов |
| `/api/admin` | admin.js | JWT + admin | Управление решениями |
| `/api/admin-panel` | admin-panel.js | JWT + admin | Панель админа |
| `/api/export` | export.js | Нет | Экспорт PDF/Excel |
| `/api/import` | upload.js | JWT | Загрузка файлов |
| `/api/upload` | inline | JWT | Альтернативная загрузка |
| `/api/recommendations` | recommendations.js | Нет | Рекомендации |
| `/api/videos` | videos.js | Нет | Видео-контент |

### Модель данных (SQLite)

Основные таблицы:
- **users** — пользователи (id, email, name, password_hash, role)
- **projects** — проекты (id, user_id, name, data JSON, timestamps)
- **industries** — отрасли (id, name, short_name, description, accent)
- **object_types** — типы объектов (id, industry_id, name, defaults JSON)
- **solution_types** — типы решений (id, name, description)
- **solutions** — решения (id, name, vendor, metrics, applicable_to, source, fit, ...)
- **parameters** — параметры объектов (object_type_id, key, label, unit, defaults)
- **catalog_sources** — источники каталога (name, type, url, last_updated)

## Расчётная модель

Расчёт экономики (`server/services/calculation.js`):

1. **Определение количества роботов**: `ceil(операции / (throughput × часы_в_год))` с корректировкой на доступность (0.95) и загрузку (0.85)
2. **CAPEX**: оборудование × (1 + коэффициенты инфраструктуры, ПО, интеграции, обучения, резерва)
3. **OPEX**: сервис + лицензии + электроэнергия + материалы + ремонт + управление
4. **Годовой эффект**: экономия ФОТ + продуктивность
5. **ROI**: (эффект × горизонт − инвестиции) / инвестиции × 100%
6. **Срок окупаемости**: первый год, когда накопленный эффект ≥ инвестиции
7. **TCO**: CAPEX + сумма OPEX за горизонт с заменой компонентов

### Сценарии

- **purchase**: стандартный расчёт с CAPEX и OPEX
- **raas**: арендная модель с ежемесячными платежами
- **base**: без роботизации (только текущие затраты)

### Чувствительность (What-if)

Варьируются три параметра: стоимость оборудования, объём операций, стоимость труда.
Для каждого: -20%, -10%, 0%, +10%, +20%.
Показывается влияние на ROI, срок окупаемости и чистый эффект.

## Фронтенд

Четырёхшаговый мастер:
1. Выбор отрасли и типа объекта (карточки с демо-данными)
2. Каталог решений (поиск, фильтры, сравнение до 3 решений)
3. Параметры объекта + расчёт + What-if + экспорт
4. Визуализация (SVG-анимация роботов на схеме объекта)

Состояние сохраняется в localStorage для восстановления сессии.

## Расширяемость

- Новые отрасли: добавить запись в `industries` + `object_types`
- Новые решения: добавить в `solutions` через админ-панель или CSV импорт
- Новые параметры: добавить в `parameters` через админ API
- Новые расчётные модули: расширить `calculation.js` с новыми сценариями
